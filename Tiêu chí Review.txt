# PROMPT: XÂY DỰNG BỘ TIÊU CHÍ CODE REVIEW CHO DỰ ÁN WEB API IoT

Bạn là **Senior Software Architect, Senior Backend Engineer và Technical Lead**, có kinh nghiệm thiết kế, phát triển và kiểm thử các hệ thống Web API tích hợp IoT.

## 1. Bối cảnh dự án

Tôi đang phát triển một hệ thống Web API phục vụ quản lý, điều khiển và giám sát thiết bị IoT.

Công nghệ dự kiến:
- Backend: ASP.NET Core Web API (.NET/C#).
- Database: SQL Server.
- ORM: Entity Framework Core.
- IoT Hardware: ESP32 và các cảm biến.
- Communication: HTTP REST API và/hoặc MQTT.
- Architecture: Clean Architecture hoặc N-Layer Architecture.
- Authentication: JWT nếu dự án sử dụng.
- Realtime: SignalR nếu dự án sử dụng.

Hệ thống có thể hỗ trợ:
- Quản lý thiết bị IoT.
- Nhận dữ liệu cảm biến.
- Giám sát trạng thái thiết bị.
- Điều khiển thiết bị từ xa.
- Lưu trữ lịch sử đo đạc.
- Cảnh báo khi vượt ngưỡng.
- Quản lý người dùng và phân quyền.

Chỉ đánh giá những tính năng, công nghệ thực sự có trong source code. Không mặc định rằng hệ thống đã triển khai tất cả các thành phần trên.

## 3. Yêu cầu về bộ tiêu chí

Với mỗi tiêu chí, hãy cung cấp:

1. **Criterion ID:** Mã tiêu chí, ví dụ ARCH-01.
2. **Criterion Name:** Tên tiêu chí.
3. **Description:** Mô tả yêu cầu kỹ thuật.
4. **Review Method:** Cách kiểm tra source code.
5. **Pass Condition:** Điều kiện đạt.
6. **Fail Example:** Ví dụ trường hợp không đạt.
7. **Severity:** Critical / High / Medium / Low.
8. **Weight:** Trọng số đánh giá.
9. **Score:** Thang điểm từ 0 đến 5.
10. **Recommendation:** Hướng cải thiện khi không đạt.

Các tiêu chí phải cụ thể, có khả năng kiểm chứng và tránh nhận xét chung chung.

## 4. Quy tắc chấm điểm

Sử dụng thang điểm:

- 0: Không đáp ứng.
- 1: Đáp ứng rất kém.
- 2: Đáp ứng một phần, còn nhiều lỗi.
- 3: Đạt yêu cầu cơ bản.
- 4: Tốt, chỉ còn một số điểm cần cải thiện.
- 5: Rất tốt, đáp ứng đầy đủ tiêu chí.

Xây dựng hệ thống trọng số theo mức độ quan trọng và tính điểm tổng trên thang 100.

Phân biệt:
- PASS: Đạt yêu cầu.
- PARTIAL: Đạt một phần.
- FAIL: Không đạt.
- N/A: Không áp dụng.
- NOT VERIFIED: Chưa đủ bằng chứng để đánh giá.

Không tính N/A vào mẫu số. Không được tự động coi NOT VERIFIED là PASS.
